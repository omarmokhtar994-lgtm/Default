# Architecture summary: Team Scheduler website (source ref 8fec106, scope webapp/ and deploy/)

**Product and principals.** Flask 3 site for contact-centre workforce management: schedules, RTA (real-time adherence) day page, leave/swaps, volumes and forecasts, shrinkage, exports. Principals: Admin (users.is_admin), Supervisor/Planner/Team manager (admin-editable permission matrix, webapp/permissions.py), Associate (only ASSOCIATE_PAGES, webapp/auth.py:15). Program scope via webapp/access.py (can_open, can_manage). Protected resources: schedules/runs and uploaded workbooks, personal data of associates, user accounts and passwords, webhook links, secret key file, the code the service runs.

**Stack.** Python, Flask, Waitress on 127.0.0.1:8080 behind Caddy (TLS, 26 MB body limit), SQLite (webapp/store.py), systemd unit as user `scheduler` (ProtectSystem=strict, only DATA_DIR writable, code sealed root-owned), CP-SAT engine run as subprocess (untouched, out of scope). No local sandbox, Flask/ortools not installed in this environment: this run is SOURCE-ONLY.

**Entry surfaces.** ~135 routes under webapp/routes/ (login, account, runs upload, volumes upload/paste, channel-needs upload, people bulk upload, exports/downloads, day/RTA POST actions, requests/swaps, admin users, notifications/webhooks, theme). Global before_request (webapp/app.py:366-420): CSRF (form token), load_user, associate wall, PERMISSION_ENDPOINTS role check, program check from request.values["program"] only. Path-id routes (my_week.py:206/224, break_changes.py:179/204, week_channels.py:240) check program inside the handler.

**Trust boundaries and strongest controls.** Sessions: signed __Host- cookie, HttpOnly, SameSite=Lax, 60-min idle, server-side revocation, password-hash stamp. Passwords: scrypt, min 10, 30-day age, lockout 5/15 min, IP throttle 40/15 min in memory keyed on remote_addr via ProxyFix(x_for=1). Uploads: PK magic, zipcheck, upload_guard, secure_filename. Outbound: webhook host allow-list (hooks.slack.com, *.logic.azure.com, *.api.powerplatform.com), redirects refused. CSP with trusted-types set in after_request. SQL: bound parameters; dynamic identifiers from whitelists (to verify).

**Source-to-sink paths of interest.** Uploaded xlsx -> openpyxl load_workbook -> engine subprocess (runs.py:277,439); volumes upload/paste (volumes_io, volumes_draft) -> parsed rows held under token -> save; exports -> csv/xlsx (formula neutralisation in webapp/exports.py:503); webhook link -> urllib send (notify.py); deploy/apply_patch.sh PATCH.json paths -> cp/rm under $PKG; install.sh env -> sed templates; update.sh zip -> pip install as root.

**Starting paths.** webapp/app.py, auth.py, access.py, permissions.py, store.py, routes/*.py, runs.py, upload_guard.py, zipcheck.py, volumes_io.py, volumes_draft.py, bulk_users.py, notify.py, exports.py, charts.py, templates/, static/app.js, deploy/*.

**Prior coverage and exclusions.** No prior ledger exists (first run). Known and already documented (docs/security/SECURITY_STATUS_2026-11-11.md), not to be re-reported as new: password padding bypass, non-ASCII CSRF 500, store-level password floor, 1h idle, 30-day expiry, unlock button, read-only code/seal, unrestricted egress (design only), SSH exposure, OS patching, MFA/backups/monitoring unverified, no absolute session cap, stored weak passwords, pip-audit date, dev-tool fixed /tmp names, service-account compromise reads data folder.

**Leads from reconnaissance (unverified).** last-admin guard missing on disable/bulk switch-off; volumes upload path may skip zipcheck/upload_guard; apply_patch.sh PATCH.json path traversal (root-run, trusted patch); ProxyFix+throttle; dynamic SQL identifiers; Content-Disposition names in volumes.py; Markup builders in charts.py; webhook DNS not pinned; HSTS without includeSubDomains.

**Companion selection.** WEB-PROTOCOL-AND-AUTH (sessions, CSRF, login, throttle, ProxyFix), DATA-ISOLATION-AND-LIFECYCLE (program scope, exports, deletion/revocation), CLIENT-SIDE (templates, charts, app.js, CSP), CLOUD-AND-DEPLOYMENT (service unit, Caddy, install), SUPPLY-CHAIN-AND-RELEASE (update/apply_patch/rollback, requirements). Excluded: MEMORY-SAFETY-AND-BINARY (pure Python, no native loader), DESKTOP-MOBILE-AND-LOCAL-IPC (web only), PROTOCOLS-RPC-AND-MESSAGING (no RPC/broker), AI-AND-LLM (no model), RESOURCE-EXHAUSTION-AND-AVAILABILITY (live availability testing prohibited; upload limits covered under Resource and file handling).
