## Q1. When does each vendor place breaks/lunches — at schedule generation, in a later pass, or intraday? Any documented "break optimization"/"activity placement" algorithm details?

### Takeaway
Almost every vendor places breaks/meals **as part of schedule generation** (breaks are modelled inside shift templates with flexible windows) **and** additionally exposes a **separate break/activity re-optimization pass** that can be run on an already-built schedule (often intraday) without moving shift start/end. The clearest documentation of a *decomposed pipeline* (headcount → shifts populated with activities/breaks → rostering) is an Amazon patent; the clearest documentation of a *multi-step local-search optimizer* that includes break moves is Calabrio (Teleopti heritage) with its named optimization steps.

### Cited Findings

**NICE (IEX WFM / NICE WFM / CXone WFM)**
- CXone WFM has "Schedule Optimization Rules" / "Optimization Plans": in a rule you select scheduling units and break activities, and "the optimizer will adjust those activities to improve the net staffing"; the generated plan "suggests schedule adjustments to the break activities" [DOC] — [CXone Help: Schedule Optimization Rules](https://help.nicecxone.com/content/workforcemanagement/optimizationrules.htm); [CXone Help: Optimization Plans](https://help.nicecxone.com/content/workforcemanagement/optimizationplanspage.htm); [Review Optimization Plans](https://help.nicecxone.com/content/workforcemanagement/optimizationplansopen.htm).
- CXone Help on generating schedules notes that "the more variations in the rules, the larger the number of possible combinations, leading to more feasible solutions and longer schedule generation times" [DOC] — [CXone Help: Generate a New Schedule](https://help.nicecxone.com/content/workforcemanagement/generatingtheschedule.htm).
- So in CXone WFM, break re-optimization is a **separate post-generation pass** (optimization plan) with an explicit **net-staffing** objective. (Break placement at generation time is implied by the rule/shift model but I could not read the full generation page.)

**Verint WFM (and Five9 Enterprise WFM, which is Verint OEM)**
- Verint's scheduling engine "incorporates all call types and other activities to generate staffing schedules that optimize agent availability, work rules, skills, holidays, breaks, service levels, and budgets" [MKT] — [Verint WFM Professional](https://www.verint.com/verint-workforce-management-professional/).
- Verint provides "the option to re-optimize the placement of breaks, meals and breaks, activity sets, task sequences, and/or activities," and one can "re-optimize breaks, meals, activity sets, task sequences, or activities without affecting shift start/end times, or along with shift start/end times"; supervisors may exclude shift items they think agents would struggle to adjust to [MKT/DOC via search extract] — [Verint WFM Professional](https://www.verint.com/verint-workforce-management-professional/); [Verint help: Generate the schedule automatically](https://wfo.mt8.verintcloudservices.com/OnlineHelp/en_US/wfm/wfm_ForeSch_generate_schedule.htm).
- A re-optimization wizard lets the supervisor select date, start time, affected agents and the set of schedule items to be re-optimized [search extract; source page attribution uncertain] — [Verint WFM product page](https://www.verint.com/workforce-management-software-wfm-solutions/).

**Genesys**
- *Genesys Multicloud/Engage WFM (PEC-WFM, docs.genesys.com / all.docs.genesys.com — NOT Genesys Cloud):* "The goal of the WFM scheduling algorithm is to minimize the over and under-staffing of agents, against the forecasted staffing requirements"; it has an **Intra-Day Schedule Rebuild Wizard** to "reoptimize the schedule day," with options to reschedule breaks, meals, activities/activity sets/task sequences, and shift start and/or end times; docs advise not reoptimizing past hours or the current hour because changes to meals/breaks would be hard to communicate [DOC] — [Intra-Day Schedule Rebuild Wizard](https://all.docs.genesys.com/PEC-WFM/Current/Supervisor/SchdRBWzdInrDy); [Scheduling Breaks and Meals](https://all.docs.genesys.com/PEC-WFM/Current/Administrator/MealsBreaks); [Scheduling](https://all.docs.genesys.com/PEC-WFM/Current/Administrator/Scheduling).
- Genesys WFM shifts have earliest/latest start time and a "Start Step" (increment between allowed start times); end times stagger correspondingly; "WFM schedules use flexible break and meal parameters" [DOC] — [Genesys WFM 8.5.2 Admin: Scheduling](https://docs.genesys.com/Documentation/WM/latest/Admin/Scheduling); [Shifts](https://all.docs.genesys.com/PEC-WFM/Current/Supervisor/Shfts).
- *Genesys Cloud WEM:* Admins can specify whether **preference fulfillment or schedule optimization** is more important [DOC via search extract] — [Genesys Resource Management use case WE02](https://all.docs.genesys.com/UseCases/Current/GenesysCloud/WE02). Genesys Cloud has "Activity plans" (placing recurring activities like meetings/training) and "Block scheduling," where work-plan activity codes "allow the schedule generation engine to optimize intraday block scheduling" and rescheduling is supported [DOC] — [Activity plans overview](https://help.genesys.cloud/articles/activity-plans-overview/); [Block scheduling overview](https://help.genesys.cloud/articles/block-scheduling-overview/).

**Calabrio ONE (calabriocloud.com line)**
- "Optimize breaks and lunches" is an action on the Agent Schedules page for current and future dates when a service queue is selected; for today, lunches/breaks must begin at least one hour from now (rounded up to 5 min) with at least 10 minutes available before the end of potential lunches/breaks; **agents are optimized in the order they appear on the page** (sortable/pinnable), across all pages [DOC] — [Calabrio ONE Help: Optimize breaks and lunches](https://calabriocloud.com/help/calabrio/user/en/Content/user-guides/agent-schedules/optimize-schedules.htm). This is a **sequential, greedy, agent-by-agent** break re-placement pass.

**Calabrio WFM (Teleopti heritage, help.calabrio.com)**
- Optimization "reallocates days off and work shifts to make the staffing levels match the forecast as closely as possible" while fulfilling work rules; there are **seven optimization steps**, including: *Days off* (moves days off within the period), *Days off for flexible work time* (uses contract day-off tolerance), *Shifts within day* (e.g., changes start time, changes activities, **moves breaks**), *Intra interval balance* (optimizes activity placement within each interval), and *Fairness* (shift-category equality or seniority-based preferred shifts) [DOC] — [How schedule optimization works](https://help.calabrio.com/doc/Content/user-guides/schedules/about-optimization-steps.htm); [Optimize schedule](https://help.calabrio.com/doc/Content/user-guides/schedules/optimize-schedule.htm); [Review optimization result](https://help.calabrio.com/doc/Content/user-guides/schedules/review-optimization-result.htm).
- Block scheduling option: shifts in a block must share "Same shift category, Same start time or Same shift"; schedule items (days off, shift category, absence) can be locked so scheduling/optimization won't change them [DOC] — [Optimize schedule](https://help.calabrio.com/doc/Content/user-guides/schedules/optimize-schedule.htm); [Lock schedule days](https://help.calabrio.com/doc/Content/user-guides/schedules/lock-schedule-days.htm).
- There is a separate help page "How moving lunches and short breaks works" (agent-tools / intraday) [DOC; not read] — [Calabrio help](https://help.calabrio.com/doc/Content/user-guides/agent-tools/about-move-lunch.htm).

### Inferences
- **Pattern across vendors: "joint-ish at generation, then separate break re-optimization."** Breaks are part of the shift model at generation (flexible windows), but every major enterprise vendor (NICE, Verint/Five9, Genesys Engage, Calabrio ONE, Calabrio/Teleopti, Assembled, Amazon, injixo) also ships a *separate* break/activity re-placement pass that holds shift start/end fixed. That strongly suggests generation-time break placement is not trusted to be final and that a cheap break-only local optimization adds measurable value.
- Calabrio ONE's documented "optimize in list order" behaviour implies a **greedy sequential** break placer (each agent's breaks placed given previous agents' placements) — a simple baseline worth replicating/beating.
- Amazon's "evaluate every possible placement window" for a single activity is an **exhaustive single-activity insertion** heuristic — also a greedy building block.

### Gaps
- Could not read full vendor pages (egress blocked); no quoted parameter lists for NICE generation settings, Verint "Generate schedule" options, or Genesys Cloud schedule generation settings.
- No primary documentation found for Aspect Workforce, Playvox WFM, or Five9 Essentials break-placement logic.
- Whether any vendor places breaks **truly jointly** (same model as shift selection) vs. heuristic insertion inside a shift-selection loop is not documented publicly, except via patents (Q4).

## Q2. What objective do they optimize (service level via Erlang C, net staffing, coverage %)? How do they score schedules? Shrinkage and multi-skill handling?

### Takeaway
Documented objectives cluster into two families: (a) **interval over/under-staffing vs. a required-staff curve** ("net staffing," "match forecast as closely as possible") — NICE optimization plans, Genesys Engage, Calabrio/Teleopti; and (b) **service-goal attainment** (service level / ASA / abandon) — Amazon Connect (explicit choice of SL or ASA), Genesys Cloud (service goal templates), Verint (service levels and budgets). For multi-skill, NICE/IEX uniquely documents **routing simulation** to estimate coverage; Amazon and Genesys Cloud use skill/staffing-group decomposition.

### Cited Findings
- **NICE:** Optimization rules adjust break activities "to improve the net staffing" [DOC] — [CXone Help: Optimization Rules](https://help.nicecxone.com/content/workforcemanagement/optimizationrules.htm). NICE claims "only NiCE WFM simulates exact ACD routing, employee skills, skill levels, and schedules with its patented formula" and considers "ASA KPIs" [MKT] — [NICE blog: How ML is optimizing schedules](https://www.nice.com/blog/how-machine-learning-is-optimizing-schedules-and-employee-experience); [NICE IEX WFM scheduling page](https://www.nice.com/products/workforce-management/nice-iex-wfm/scheduling).
- **IEX patent basis for multi-skill:** US6044355 (IEX) states the central problem of skills-based scheduling is predicting "what fraction of scheduled agents from each skill group will be available to each call type during each time interval," that no satisfactory direct calculation exists, and proposes "a feedback mechanism involving call handling simulation and incremental scheduling" [PAT] — [US6044355 (USPTO PDF)](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/6044355); related IEX patent US6970829 "skills-based planning and scheduling" (assigned to IEX Corporation) [PAT] — [Google Patents US6970829B1](https://patents.google.com/patent/US6970829B1/en).
- **Genesys Engage WFM:** "The goal of the WFM scheduling algorithm is to minimize the over and under-staffing of agents, against the forecasted staffing requirements" [DOC] — [Genesys WFM Scheduling](https://all.docs.genesys.com/PEC-WFM/Current/Administrator/Scheduling).
- **Genesys Cloud:** Service goal templates (business-unit level) contain service level, ASA and abandon-rate targets and are assigned to **planning groups**; "schedule generation looks for agents who can handle the entire planning group" — agents who can handle only a subset "will not be scheduled based on workload, but will receive a schedule" [DOC] — [Planning groups key principles](https://help.genesys.cloud/articles/planning-groups-key-principles/); [Add a service goal template](https://help.mypurecloud.com/articles/add-a-service-goal-template/); [Route paths / SGT / planning groups FAQ](https://help.genesys.cloud/faqs/what-is-the-relationship-between-route-paths-service-goal-templates-and-planning-groups/).
- **Calabrio/Teleopti:** optimization makes "staffing levels match the forecast as closely as possible" while fulfilling work rules; the Fairness step is a secondary objective [DOC] — [How schedule optimization works](https://help.calabrio.com/doc/Content/user-guides/schedules/about-optimization-steps.htm).
- **Verint:** engine optimizes against "agent availability, work rules, skills, holidays, breaks, service levels, and budgets" [MKT] — [Verint WFM Professional](https://www.verint.com/verint-workforce-management-professional/). Verint holds a patent "System and method for automatic shrinkage forecasting" (US10037500) [PAT; content not read] — [USPTO PDF 10037500](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/10037500).
- **Amazon Connect:** "designed to generate the least number of shifts for agents based on the forecasted demand pattern and configured constraints to hit the optimization goal," choosing **service level or average speed of answer** as the goal [DOC/MKT] — [Amazon Connect optimization](https://aws.amazon.com/products/connect/customer/optimization/); [Scheduling in Amazon Connect](https://docs.aws.amazon.com/connect/latest/adminguide/scheduling.html). Multi-skill forecasting/scheduling launched Nov 2025, segmenting demand by skills (departments, languages, customer tiers); limits ~350 agents per staffing group, 300 staffing groups per forecast group; June 2026: up to 5,000 agents per schedule [DOC/What's New] — [Multi-skill scheduling](https://docs.aws.amazon.com/connect/latest/adminguide/multiskill-scheduling.html); [What's New 2025-11](https://aws.amazon.com/about-aws/whats-new/2025/11/amazon-connect-multi-skill-agent-scheduling); [What's New 2026-06: 5,000 agents](https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-connect-customer-5000-agents/); [Staffing groups](https://docs.aws.amazon.com/connect/latest/adminguide/scheduling-create-staffing-groups.html).
- **Assembled:** claims to find "the optimal solution that maximizes coverage while respecting every constraint" [MKT] — [Assembled blog](https://www.assembled.com/blog/ai-powered-schedule-generation). Event optimization maximizes coverage (e.g., around chat time) [DOC] — [Event optimizations](https://support.assembled.com/hc/en-us/articles/4418096297613-Event-optimizations).
- **Talkdesk:** marketing claims schedules consider KPI trends, CSAT, skill level, with ML suggestions [MKT] — [Talkdesk WFM](https://www.talkdesk.com/cloud-contact-center/wem/workforce-management/workforce-management-wfm/).

### Inferences
- "Net staffing" (scheduled − required, per interval) is the de-facto scoring currency for break/activity re-optimization passes; SL/ASA goals typically enter upstream through the required-staff calculation (Erlang-type or simulation) rather than being optimized directly in the break pass. Amazon's activity placement is the exception that states SL attainment directly.
- Multi-skill approaches split into (1) **simulation-in-the-loop** (NICE/IEX patent lineage) vs. (2) **decomposition into groups** (Genesys Cloud planning groups; Amazon staffing groups and the Amazon group-decomposition patent in Q4).
- Shrinkage is universally applied as an input adjustment to requirements; I found no vendor documenting shrinkage as an optimized variable.

### Gaps
- No public vendor doc states the exact scoring function (e.g., squared vs. absolute over/under, asymmetric weights for understaffing, SL-curve concavity).
- Schedule quality metrics shown to users (e.g., "coverage %," "net staffing chart," "SL projected") are likely in UI docs I could not open; Calabrio has a "Review optimization result" page that likely lists them — [link](https://help.calabrio.com/doc/Content/user-guides/schedules/review-optimization-result.htm).
- No reliable data on how NICE handles language as a skill vs. separate queue.

## Q3. Do they run multiple candidate schedules/iterations and pick the best? Guidance on "number of passes"/"optimization level"?

### Takeaway
Only NICE publicly documents a user-controllable multi-pass/iterative process ("Closed Loop Schedule Optimization": user sets number of passes and time allowed; best schedule returned; early stop if a pass is good enough). Others expose multi-step pipelines (Calabrio's seven optimization steps) or time/complexity warnings, but I found no published "number of iterations" guidance from Verint, Genesys, Aspect, Assembled, Talkdesk, Five9 or Amazon.

### Cited Findings
- NICE: "Closed Loop Schedule Optimization... starts with some self-educated 'guesses,' then learns and fine-tunes information with each successive iteration of a planning and scheduling 'pass'"; "the user can determine how many passes and how much time to allow the system to run through this learning process"; "after running through multiple schedule combinations, the tool will present you with the most optimal schedule possible"; it "is intelligent enough to recognize if one of the initial passes is good enough to be the final schedule set" [MKT] — [NICE blog: The AI tools CXone WFM offers today](https://www.nice.com/blog/the-ai-tools-cxone-wfm-offers-today); [NICE blog: How ML is optimizing schedules](https://www.nice.com/blog/how-machine-learning-is-optimizing-schedules-and-employee-experience).
- NICE: more rule variations → more combinations → more feasible solutions and longer generation time [DOC] — [CXone Help: Generate a New Schedule](https://help.nicecxone.com/content/workforcemanagement/generatingtheschedule.htm).
- Calabrio/Teleopti: optimization is split into (seven) selectable steps (days off, days off for flexible work time, shifts within day, intra interval balance, fairness, etc.) that the scheduler chooses to run [DOC] — [How schedule optimization works](https://help.calabrio.com/doc/Content/user-guides/schedules/about-optimization-steps.htm); [Optimize schedule](https://help.calabrio.com/doc/Content/user-guides/schedules/optimize-schedule.htm).
- Genesys Cloud: explicit trade-off setting between preference fulfillment and schedule optimization [DOC] — [Genesys WE02](https://all.docs.genesys.com/UseCases/Current/GenesysCloud/WE02).
- Talkdesk: bug where "consistent start time prevented optimal schedules from being considered" indicates candidate filtering by rule toggles [DOC] — [Talkdesk release notes](https://support.talkdesk.com/hc/en-us/articles/10465941906203-Release-Notes-Talkdesk-Workforce-Management).

### Inferences
- NICE's "passes" description is consistent with the IEX patent's simulate→adjust→reschedule feedback loop (Q4): each pass re-estimates multi-skill coverage by simulation and reschedules, keeping the best schedule set. "Machine learning" in the marketing likely refers to this iterative feedback rather than a trained model (inference; not documented).
- Calabrio's step-wise design implies a **variable-neighbourhood / multi-phase local search**: separate neighbourhoods for days-off moves, shift swaps within day, break moves, and intra-interval activity balancing, run in user-selected order.
- For an in-house scheduler, the market evidence supports (a) exposing a time budget / number of passes, (b) keeping best-so-far, and (c) early-stopping when improvement stalls.

### Gaps
- No vendor published recommended pass counts or time limits; no public benchmark of improvement per pass.
- "Schedule sets" (NICE/IEX term for a generated set of schedules) was not found documented in a readable source beyond NICE's blog phrase "final schedule set."

## Q5. Practical lessons: rules that measurably improve coverage (staggered starts, flexible break windows, break rules by interval, shift bidding)

### Takeaway
Vendor guidance consistently says flexibility widens the feasible space and improves coverage (at the cost of run time): wider break/lunch windows, finer start-time steps with staggered start ranges, variable start times by day, non-5×8 patterns, staggering of lunch events to avoid spikes, and locking items you don't want moved. I found no vendor-published quantified coverage gains.

### Cited Findings
- Verint blog recommends expanding the windows for breaks and lunches, letting each employee's shift start vary by day of week by as little as an hour, offering pay premiums for non-fixed-hours work, and moving beyond 5×8 to patterns like 4×10 that match volume [MKT] — [Verint blog: Are You Managing Your Schedules—Or Optimizing Them?](https://www.verint.com/blog/are-you-managing-your-schedules-or-optimizing-them/).
- NICE: more rule variations → more feasible solutions but longer generation times [DOC] — [CXone Help: Generate a New Schedule](https://help.nicecxone.com/content/workforcemanagement/generatingtheschedule.htm).
- Genesys WFM: staggered start ranges (earliest/latest start) with a "Start Step" granularity, matching end-time stagger, flexible break/meal parameters [DOC] — [Genesys WFM Scheduling](https://docs.genesys.com/Documentation/WM/latest/Admin/Scheduling); [Shifts](https://all.docs.genesys.com/PEC-WFM/Current/Supervisor/Shfts).
- Genesys Engage: don't reoptimize the current hour — breaks/meals changes are hard to communicate [DOC] — [Intra-Day Schedule Rebuild Wizard](https://all.docs.genesys.com/PEC-WFM/Current/Supervisor/SchdRBWzdInrDy). Calabrio ONE enforces a ≥1 hour lead time for intraday break optimization [DOC] — [Calabrio ONE: Optimize breaks and lunches](https://calabriocloud.com/help/calabrio/user/en/Content/user-guides/agent-schedules/optimize-schedules.htm).
- Assembled's "stagger events" option randomizes among equally optimal placements so lunches don't cluster [DOC] — [Event optimizations](https://support.assembled.com/hc/en-us/articles/4418096297613-Event-optimizations).
- Amazon: relative-to-shift windows (e.g., ≥1h after start, ≥2h before end) as a break/activity constraint style [DOC/MKT] — [AWS blog: Optimize activity placement](https://aws.amazon.com/blogs/contact-center/optimize-activity-placement-in-amazon-connect-scheduling/).
- Talkdesk: a break rule that doesn't fit a shift can force schedules outside min/max hours; fixed break offsets relative to shift start; "consistent start time" can exclude optimal schedules [DOC] — [Talkdesk troubleshooting](https://support.talkdesk.com/hc/en-us/articles/9696400718107-WFM-Schedule-Troubleshooting-Checklist); [Talkdesk release notes](https://support.talkdesk.com/hc/en-us/articles/10465941906203-Release-Notes-Talkdesk-Workforce-Management).
- Calabrio: lock days off/shift categories/absences to protect them from optimization; block scheduling (same category/start/shift) trades coverage for consistency [DOC] — [Lock schedule days](https://help.calabrio.com/doc/Content/user-guides/schedules/lock-schedule-days.htm); [Optimize schedule](https://help.calabrio.com/doc/Content/user-guides/schedules/optimize-schedule.htm).
- Genesys Cloud: explicit knob trading preference fulfillment vs. optimization [DOC] — [Genesys WE02](https://all.docs.genesys.com/UseCases/Current/GenesysCloud/WE02).

### Inferences
- Consistency constraints (consistent start times, block scheduling, fixed break offsets) are the most common documented cause of coverage loss; flexible windows and a follow-up break-only re-optimization pass are the most common documented remedies.
- A practical design for an in-house scheduler mirroring vendor practice: generate shifts+days off with breaks in flexible windows → run a break/activity-only local search scored by interval net staffing (with a staggering/tie-break randomization) → allow intraday re-runs with a lead-time cutoff and lockable items.

### Gaps
- No quantified before/after coverage or SL improvements from any vendor, SWPP talk, or analyst report were found.
- Shift bidding guidance and "break rules by interval" (e.g., max % of staff on break per interval) were not found in the sources I could retrieve.
