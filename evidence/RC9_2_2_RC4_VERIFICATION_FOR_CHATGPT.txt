3. NEW ISSUE FOUND IN RC4
--------------------------

N1 — MEDIUM — the all-days aliases are unreachable; natural spellings hard-fail.

_parse_language_days accepts an all-days value via:
      norm(text) in {"all", "alldays", "daily", "everyday", "7days"}

norm() does not strip spaces:
      norm('All Days')  = 'all days'   -> NOT in the set
      norm('Every Day') = 'every day'  -> NOT in the set
      norm('7 Days')    = '7 days'     -> NOT in the set
      norm('All')       = 'all'        -> matches
      norm('Daily')     = 'daily'      -> matches

So three of the five aliases can never match, and the two most natural things a
scheduler types — "All Days" and "Every Day" — are now a HARD preflight failure:
      'All Days'  -> preflight FAIL ['INVALID_LANGUAGE_COVERAGE_DAYS']
      'Every Day' -> preflight FAIL ['INVALID_LANGUAGE_COVERAGE_DAYS']

This is the THIRD recurrence of the A51 defect pattern: an alias list written
against an assumption about norm() that does not hold. The work-around applied
was to edit the Voice workbook ("Corrected the Voice Coverage Days list to use
canonical All rather than All Days") rather than fix the normaliser.

It now fails closed rather than open, so it is not a safety hole — but a live
scheduler typing the most obvious value gets a blocked run with no hint that
"All" would have worked.

FIX (one line, and it retires the whole defect class):
      key = re.sub(r"[^a-z0-9]", "", norm(text))
      if not key or key in {"all", "alldays", "daily", "everyday", "7days"}:
Apply the same collapse to the token aliases. Also add the accepted vocabulary
to the Coverage Days cell's Excel dropdown so the value cannot be typed free-form.
