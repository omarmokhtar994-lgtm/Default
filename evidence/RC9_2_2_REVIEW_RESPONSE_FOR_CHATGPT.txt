F1 — CRITICAL — the +3 target / -9 floor failure returns
File: engine/_tools/l632_universal_scheduler.py
Function: target_priority_tradeoff_select (approx. lines 9838-9962)

risk_ok ANDs five GLOBAL DOMINANCE tests (severity_ok, concentration_ok,
depth_ok, boundary_ok, hard_floor_ok). Each asks "does any other candidate beat
me on this axis at greater-or-equal target". With three or more candidates these
can eliminate EVERY candidate simultaneously. The fallback
"accepted = risk_eligible or pool" then reverts to a PURE TARGET-FIRST SORT.

Reproduction (target_ratio=0.90, floor_ratio=0.80, production defaults):
  SAFE    after_target=150  after_floor=160  severe=2  run=2  depth=0.10  overage 40.0
  GREEDY  after_target=153  after_floor=151  severe=9  run=6  depth=0.40  overage 48.0
  ODD     after_target=150  after_floor=158  severe=0  run=8  depth=0.50  overage 60.0

  With {SAFE, GREEDY} only: guard WORKS. SAFE risk_ok=True, GREEDY blocked by
  one trade-off blocker, SAFE selected. The new tradeoff_blockers test is good.

  Adding ODD — an ordinary candidate best on one safety axis at the same target:
    SAFE    risk_ok=False (severity_ok=False: ODD has 0 severe at equal target)
    GREEDY  risk_ok=False (1 trade-off blocker)
    ODD     risk_ok=False (concentration_ok=False, depth_ok=False)
    guard accepted anybody? False -> accepted = pool -> target-first sort
    PICKED: GREEDY. vs SAFE: target +3, floor -9, severe +7, overage +8.0 FTE

That is the NMG EN+SP trade restored, by the code written to prevent it.

Collapse rate rises with pool size (random pools, same distribution):
    pool=10   accepted by guard 1/10
    pool=25   accepted by guard 1/25
    pool=50   accepted by guard 0/50    <- collapsed
    pool=100  accepted by guard 0/100   <- collapsed
So this is not a corner case; it is the expected behaviour on DEEP-run pool
sizes. Cost is not the problem (19 ms at n=100).

Not rescued downstream: recommendation_anchor becomes GREEDY, and
genuinely_safer_than_strict only promotes candidates within
primary_target_tolerance, which defaults to 1 and is hard-coded as '1' in
RUN_UNIVERSAL_PRODUCTION.py. SAFE at 150 is 3 below and cannot be promoted.

RECOMMENDED FIX (two parts):
  a) Make the fallback protected-safe. It must not revert to target-first.
     Either relax one axis at a time until the set is non-empty (recording
     which axis was dropped, for audit), or sort the fallback by the
     protected-tier key rather than by target.
  b) Restore severity/concentration/depth as ANCHOR-RELATIVE THRESHOLDS — the
     pre-hardening form (severe <= max(anchor_severe + 2, 2)) could not empty
     the set — and KEEP tradeoff_blockers, which is the part that works.


F2 — HIGH — the language working window is the rejected semantics
File: engine/_tools/l632_universal_scheduler.py
Function: shift_within_language_window (line 1804)

RC2 forked before Claude commit 99d0a16b and still requires the WHOLE SHIFT to

F3 — MEDIUM — language repair planner asks about the wrong day
File: engine/_tools/l632_universal_scheduler.py
Function: language_break_overlap_repair_plan (approx. line 6199)

    day=(0 if qslot >= TOTAL_QSLOTS else day_scope)

day_scope IS correctly rebound per key at line 6154
(`day_scope, interval_index, _ = key`). qslot is NOT — it is a leftover from the
earlier pattern/break scan loop (line 6086). The correct idiom already exists
110 lines above at line 6091: `data_day = day_scope if day_scope < 7 else 0`.

TOTAL_QSLOTS = 672, so a next-Sunday slot has day_scope == 7, and day=7 matches
nothing because active_days is always a subset of {0..6}:

    rules in force at 10:00 (one all-day rule + one Sun-Thu rule):
      day=0 -> ['Spanish', 'International']
      day=4 -> ['Spanish', 'International']
      day=5 -> ['Spanish']            (correct: International is Sun-Thu)
      day=6 -> ['Spanish']
      day=7 -> []                     (everything vanishes)

Two failure directions:
  - day_scope==7 with stale qslot < 672 -> day=7 -> the donor eligibility filter
    sees zero rules -> NO DONORS are added to the next-Sunday language repair
    focus at all.
  - day_scope<7 with stale qslot >= 672 -> day=0 -> matches Sunday's rules for a
    mid-week key, which is wrong once day-specific rules exist.
Which one fires depends on where the previous loop stopped, so it is also
input-dependent and non-deterministic in effect.

This sits in the same area as the Cricut Chat failure (12 next-Sunday floor
gaps). Not claiming causation — that needs a run — but a repair path that
silently finds no donors is a plausible contributor and it fails quietly.

RECOMMENDED FIX:
    day=(0 if day_scope >= 7 else day_scope)
plus: make language_rules_at normalise or reject day outside 0..6 instead of
returning []. An out-of-range day currently reads as "no language rules apply
anywhere", which is the most dangerous possible default for a coverage rule and
is why this stayed invisible.

6. DESIGN RECOMMENDATION
-------------------------
There is still no single canonical language evaluator. language_rules_at,
associate_language_window, shift_overlaps_required_language_for_noneligible and
the validator's own copy each re-implement part of the semantics. That is why
day=7 can silently mean "no rules" in one caller and nothing anywhere else, and
why F5 and F8 are still open. Your section 5 recommendation is correct; F3, F5
and F8 are all symptoms of its absence.

Coverage Split (Claude branch) has the same requirement — window overlap,
directional eligibility, pooled vs independent group semantics, reserve, break
impact — and should be folded into that same evaluator DURING the merge rather
than bolted alongside it afterwards.

8. ANSWER TO "IS THIS SAFE FOR LIVE SCHEDULES?"
------------------------------------------------
No. Keep RC9.1 as the operational baseline, exactly as RELEASE_STATUS.json says.

RC2 is materially safer than the original Claude package on the release chain,
identity, sealing and fixed-row semantics — those fixes are real and were
verified in source here. But it is not safe for unattended live use:

  - F1 means the candidate that reaches a published roster can still be the one
    that trades protected coverage for target intervals, and the collapse gets
    MORE likely as the candidate pool grows.
  - F2 means the language working window will refuse schedules that are
    actually achievable.
  - F8 means a day-scoped language rule can silently apply on days the business
    excluded.

Neither build should ship on its own. The merge, plus F1, F3 and F8, is the
shortest path to a defensible release candidate.
